# AppleSupport AI agent — Hiver SDE Intern take-home

An AI support agent for **@AppleSupport**, built from the
[Customer Support on Twitter](https://www.kaggle.com/datasets/thoughtvector/customer-support-on-twitter)
dataset. Given an incoming customer tweet it:

1. **classifies** it into one of 10 intents induced from the data,
2. **drafts a reply** grounded in how AppleSupport historically answered similar tweets,
3. **decides auto-handle vs. escalate**, with a stated reason.

The system is the easy half. The evaluation is the deliverable — see
[REPORT.md](REPORT.md), particularly the section on what the headline number hides.

---

## Quick start with `make`

```bash
make setup                 # .venv + requirements + .env (then fill in your API key)
make data                  # download TWCS, build splits, validate golden set
make quick                 # baselines -> agent -> judge -> evaluate on 25 cases
make run                   # the full 220-case headline run
make web                   # demo dashboard at http://localhost:5001
make ask TWEET="my iphone won't charge past 80%"   # try the agent on one tweet
make smoke                 # stubbed-LLM wiring test, no API key needed
```

`make help` lists every target. `LIMIT=`, `MODEL=` and `WORKERS=` pass through to the agent.

## Reproduce the headline results in under 15 minutes

Requires Python 3.10+ and an API key for any OpenAI-compatible provider.

```bash
pip install -r requirements.txt
cp .env.example .env        # then edit: LLM_BASE_URL, LLM_MODEL, LLM_API_KEY, JUDGE_MODEL
```

```bash
python src/prepare_data.py      # downloads TWCS, rebuilds 80,176 AppleSupport cases  (~4 min)
python src/make_splits.py       # corpus / dev / golden splits, asserts no leakage      (~2 min)
python src/build_golden.py      # validates the 220 hand-labelled golden cases          (instant)
python src/baselines.py         # B0 trivial + B1 TF-IDF/LogReg                         (~2 min)
python src/agent.py             # the agent on all 220 golden cases                     (see note)
python src/judge.py             # LLM-as-judge scores every reply
python src/evaluate.py          # prints the results table -> reports/results.json
```

**Note on runtime.** Wall-clock for `agent.py` is dominated by your provider's rate
limit, not by compute. On Groq's free tier (8,000 tokens/min) the full 220-case run
takes ~50 minutes. Every LLM call is cached on disk by content hash, so a second run
is instant and byte-identical. To see the pipeline work end-to-end in two minutes:

```bash
python src/agent.py --limit 25 && python src/judge.py && python src/evaluate.py
```

`agent.py` is resumable — rerun the same command and it retries only what failed.

To verify the wiring with no API key and no cost at all:

```bash
python src/smoke_test.py        # stubbed LLM, exercises agent -> judge -> evaluator
```

| Path | What it is |
|---|---|
| `src/prepare_data.py` | Flat tweet table → reconstructed conversation threads → cases |

| `src/agent.py` | classify → ground → draft → route |
| `src/judge.py` | Reference-free LLM-as-judge rubric |
| `src/judge_agreement.py` | Judge vs. human: raw agreement, Cohen's kappa, direction of bias |
| `src/baselines.py` | B0 trivial, B1 TF-IDF + logistic regression |
| `src/metrics.py` | Metrics with bootstrap CIs; escalation treated asymmetrically |
| `src/evaluate.py` | Scores every system, emits `reports/results.json` |

## The taxonomy

Induced by clustering 12k customer openers (k=28), then hand-consolidated into
intents that differ in **what the agent must do**, not in subject matter.

| Intent | Default route |
|---|---|
| `software_bug` | auto |
| `battery_charging` | auto |
| `connectivity` | auto |
| `app_service` | auto |
| `how_to` | auto |
| `feedback_no_action` | auto |
| `account_billing` | escalate |
| `hardware_repair` | escalate |
| `data_loss` | escalate |
| `unclear` | escalate |

The default is a prior, not the decision — the agent overrides per case, and must,
because an abusive `how_to` still escalates.

Escalation reasons: `needs_private_data`, `irreversible_risk`, `relationship_risk`,
`safety_risk`, `insufficient_info`, `no_known_remedy`.
